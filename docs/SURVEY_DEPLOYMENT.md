> 관련: [`STACK_DECISION.md`](./STACK_DECISION.md)(인프라 결정), [`PRODUCTION_PLAN.md`](./PRODUCTION_PLAN.md)(로드맵)

## 1. 맥락

부산도시공사(이하 BMC) 김준우 대리 요청으로, 해커톤 출품작 **Be:live**를 BMC **청약센터**(https://apply.bmc.busan.kr/) 공지사항에 게시해 시민·직원 대상 설문을 진행한다. 설문 목적은 청약센터(내부: 청약관리시스템) 개선 의견 수렴이다.

| 항목 | 내용 |
|---|---|
| 운영 기간 | 2026년 9월 말 ~ 2027년 2월 (약 5개월) |
| 사전 작업 | 2026년 9월 중순 오류 최소화(기능 작동 확인 후 조치) |
| 예상 트래픽 | 월 방문자 100명 |
| 비용 부담 | BMC — 단, 사전 예상 비용 또는 견적서·영수증 제공 필요 |
| 회신 기한 | 2026년 8월 26일(수) |

BMC 요청 지원 범위 3가지: ① 설문 기간 서비스 운영 ② BMC 맞춤형 구현(LH 등 BMC 관리 외 임대주택 제외) ③ 사용자 기능 설명서 1~2장.

**이 배포는 실서비스 전환이 아니라 설문용 체험 서비스 운영이다.** 그 전제가 아래 모든 결정의 기준이다.

## 2. 확정 결정

| 영역 | 결정 |
|---|---|
| 호스팅 | **Cloudflare Pages** 정적 배포 + Pages Function 1개 |
| 배포 방식 | `wrangler pages deploy` 로컬 직접 업로드 (Git 연동 미사용) |
| 저장소 | 현재 **public 유지**, 발제사 데이터는 비커밋 |
| AI 모델 | **Gemini Flash** (`gemini-flash-latest`, 무료 티어) |
| 백엔드·DB | **런타임 미사용** — NestJS·PostGIS는 개발·검증용으로만 유지 |
| 개인정보 | **수집하지 않음** — 로그인·동의 화면 없음 |
| 청약 신청 | 자체 처리하지 않고 BMC 청약센터로 위임 |

### 2.1 왜 정적 배포로 충분한가

앱이 서버 없이 완결되는 구조다.

- 355단지 데이터(`frontend/src/generated/housings.json`, 842KB)가 번들에 포함되고, MSW가 브라우저 안에서 `/api/housings`를 응답한다.
- 취향 적합도 랭킹은 `rankByLearnedPreference`가 브라우저에서 계산한다(`preference-features.json`, 258KB).
- 찜·필터 조건은 `localStorage`(`bmc-store`)에만 저장된다.
- 상권 GIS 8피처 산출(`tag/` 파이프라인)은 빌드 이전에 로컬에서 1회 실행되고, 결과 JSON만 번들에 실린다.

런타임에 서버가 필요한 곳은 **AI 자연어 검색 하나뿐이며, 이유는 연산이 아니라 API 키 은닉**이다. `handlers.ts:29`의 `VITE_AI_PROXY` 분기가 이 하이브리드 구성(목데이터 + 실 AI + 키 미노출)을 이미 지원한다.

### 2.2 왜 Cloudflare인가

- 무료 플랜에서 **상업·기관 용도가 허용된다.** Vercel Hobby는 약관상 금지라 Pro($20/월)가 필요하다.
- 정적 트래픽·요청 수 무제한, Workers 무료 한도 10만 건/일. 월 100명 트래픽의 1% 미만.
- 서울 엣지에서 서빙된다.

### 2.3 왜 Git 연동 대신 직접 업로드인가

`.gitignore:30-32`가 발제사 데이터 3종을 커밋 제외한다. Git 연동 빌드는 합성 데모 데이터로 빌드되어 355단지가 뜨지 않는다. 로컬 빌드 결과물만 올리면 데이터가 Git 히스토리에 남지 않아 저장소 공개 정책이 유지되고, public 수상작 포트폴리오도 그대로 둘 수 있다.

배포 빈도가 낮아(9월 오픈 1회 + 오류 수정 수회) 자동 배포의 이득이 작다는 점도 근거다.

### 2.4 AI 모델 — Gemini Flash 무료 티어

기존 개발 경로와 동일한 모델·프롬프트·스키마를 그대로 쓴다. 배포 경로와 로컬 개발 경로가 같은 모델을 쓰므로 검증한 동작이 그대로 나간다.

`gemini-flash-latest`를 쓴다. lite 모델은 멀티턴 되묻기에서 출력 폭주·구조화 누락이 발생해 부적합하다(P5-C-4).

무료 티어의 두 가지 조건을 전제한다.

- **일일 1,500 요청 한도** — 월 100명 기준 예상 사용량(월 약 400건)의 100배 이상 여유가 있다.
- **입력이 Google 제품 개선에 사용된다** — 전송되는 것은 사용자가 입력한 검색 문장뿐이며 개인 식별정보는 포함되지 않는다.

## 3. 비용

대외 제출용 산정서는 바탕화면 `belive-BMC설문운영-비용산정서.docx`가 정본이다(저장소에 두지 않는다). 여기에는 결정 근거와 요약만 남긴다.

**견적은 Claude Sonnet 5 기준, 실제 배포는 Gemini 무료 티어로 운영한다.** 승인 예산 안에서 언제든 모델을 상향할 수 있게 여유를 둔 것이며, 전환 전까지 AI API 실지출은 0원이다.

| 구분 | 6개월 |
|---|---|
| 견적서 총액 (Claude 기준, 월 100명) | ₩99,780 |
| 견적서 상한 (API 월 상한 $30 적용) | ₩278,700 |
| 현재 실지출 (Gemini 무료 운영 시) | 도메인 ₩23,100 |

무료 한도로 처리되는 항목: Cloudflare Pages(요청·트래픽 무제한), Cloudflare Workers(일 10만 건), Naver Maps(월 1,000만 건), VWorld 지오코딩(빌드 시 1회, 캐시).

도메인은 `be-lieve.co.kr`(KISA whois 확인 결과 등록 가능)을 전제로 정상가 23,100원으로 계상했다. 무료 서브도메인(`bmc-housing.pages.dev`)을 쓰면 이 항목도 0원이 된다.

## 4. 개인정보 처리

**시민 개인정보를 수집·보관하지 않는다.**

| 항목 | 처리 |
|---|---|
| 로그인 | 없음 |
| 서버 저장 | 없음 (런타임 DB 미사용) |
| 브라우저 저장 | 찜한 단지 ID, 필터 조건, 취향 가중치 8개 — `localStorage`에만 |
| 외부 전송 | AI 검색 시 **사용자가 입력한 검색 문장만** Google(Gemini)로 전송. 개인 식별정보 없음 |
| 신청 자격 | 무주택 여부·소득구간 등 범주형 선택지. 필터링 전용, 세션 스토어에만 보관 |

이에 따라 **개인정보 영향평가 대상이 아니며, 개인정보 처리 수탁 계약도 성립하지 않는다.** 해외 CDN 사용에 따른 국외이전 이슈도 발생하지 않는다. 공공기관 내부 승인 절차를 단축하는 요소이므로 회신에 명시한다.

AI 검색의 외부 전송 사실은 사전 고지가 필요하다. 문제가 되면 AI 검색만 비활성화해도 나머지 기능은 정상 동작한다.

## 5. 서비스 범위 조정

### 5.1 로그인·개인정보 동의 화면 없음

설문 대상 서비스로 공개하는 이상 두 화면은 두지 않는다.

- **동의 화면** — 수집하지 않는 개인정보에 동의를 받는 것은 공공기관 서비스에서 사실과 다른 고지가 된다.
- **로그인 화면** — 시민이 청약센터 실계정 아이디·비밀번호를 입력할 위험이 있다. 값을 저장·전송하지 않더라도 입력을 유도하는 화면 자체가 부적절하다.

계정이 없으므로 전 화면이 공개이고 라우트 가드도 없다. 첫 화면은 조건 설정(`/setup`)이며 첫 진입 팝업이 서비스 성격을 고지한다(확인 시 `noticeSeen`으로 재노출 차단):

- 개인정보를 수집·보관하지 않음
- 로그인이 없고 선택 조건·취향·관심 목록은 이 브라우저에만 저장, 서버 전송 없음
- 실제 청약 신청·자격 조회는 BMC 청약센터에서 진행

AI 검색의 외부 전송 고지는 AI 검색 패널 상단에 둔다.

### 5.2 BMC 맞춤형 요건은 이미 충족

데이터가 BMC 제공 CSV 100%다 — 매입임대 336, 재개발임대 11, 행복주택 7, 통합공공임대 1, 합계 355단지. LH 등 타 기관 임대주택이 애초에 포함되지 않아 추가 작업이 없다.

### 5.3 청약 신청 처리

자체 처리하지 않는다. `DetailScreen.tsx`의 "청약센터 바로가기"가 BMC 청약센터로 이동시키고, 본인인증이 필요하다는 안내를 함께 노출한다. 우리 서비스는 **어디에 살지 고르는 단계**를 맡고 신청은 기존 시스템이 맡는 역할 분담이다. 청약센터 공지에서 진입해 다시 청약센터로 돌아가는 흐름이 설문 목적과도 맞는다.

## 6. 배포 절차

1. `frontend/public/_redirects`에 `/* /index.html 200` — SPA 딥링크 처리
2. 저장소 루트 `functions/api/search/nl.ts` — Gemini 프록시 (`backend/src/search/search.service.ts`의 프롬프트·스키마를 그대로 이식)
3. 빌드 시점 변수 `frontend/.env.production` — `VITE_AI_PROXY=1`, `VITE_NAVER_MAP_CLIENT_ID`
   - `VITE_API_BASE_URL`은 설정하지 않는다 — 설정하면 MSW가 꺼져 목록이 비게 된다(`main.tsx:56`)
   - `VITE_GEMINI_API_KEY`는 설정하지 않는다 — 번들에 키가 박힌다
4. 런타임 시크릿 `npx wrangler pages secret put GEMINI_API_KEY`
5. 배포 `npm run build -- --base=/` → `npx wrangler pages deploy frontend/dist`
   - `--base=/`는 `vite.config.ts:6`의 GitHub Pages용 하위 경로 설정을 덮어쓴다. 라우터 `basename`과 MSW 워커 경로가 `BASE_URL`을 읽으므로 자동으로 따라온다
6. Cloudflare 커스텀 도메인 연결 + **NCP 콘솔에 배포 도메인 등록** (누락 시 지도 미표시)
7. Cloudflare 대시보드 Rate limiting rules로 `/api/search/nl` 보호 (KV 없이 처리)

### 배포 후 확인

`/map` 새로고침 무오류 · 지도 마커 표시 · 목록 355건 · AI 검색 조건 칩 생성 · 번들에 `AIza` 문자열 부재(키 미노출).

## 8. 재검토 조건

- **설문 결과로 실서비스 전환이 결정될 때** — 실 OAuth·본인인증·청약 연동이 필요해지고, 그 순간 개인정보를 다루게 된다. 국내 리전 DB·컬럼 암호화·접근통제·백업·개인정보 영향평가가 전제 조건이 되며, 비용의 주축이 인프라에서 규제 대응으로 옮겨간다. [`STACK_DECISION.md`](./STACK_DECISION.md)가 채택한 self-host 구성이 이때 실제로 쓰인다.
- **BMC가 국내 사업자 인프라를 요구할 때** — 프론트가 정적 파일 묶음이라 AWS Lightsail 서울(월 약 ₩17,000) 또는 NCP로 옮기는 비용이 거의 없다.
- **트래픽이 예상을 크게 웃돌 때** — Naver Maps는 여유가 크고, Gemini 일 1,500 요청 한도를 넘어설 때만 유료 전환을 검토한다.

> 이 결정은 [`STACK_DECISION.md`](./STACK_DECISION.md) §7의 재검토 조건 1번("데모 목표가 발표자 로컬 구동에서 상시 링크로 바뀔 때")에 따라 내려졌다. self-host 채택 자체를 뒤집지 않으며, 설문 기간에 한해 정적 배포를 택한 것이다.
