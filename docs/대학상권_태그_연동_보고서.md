## 1. 편입 대상 — 대학상권 태그 한 갈래

- **대학 전처리**(`prepare-universities.mjs`): 전국 표준데이터 → 부산 대면 대표 캠퍼스 25곳 정규화, 선도소프트 주소점 정확주소 좌표 결합.

## 4. 태그 정의와 산식

| 태그 | 역할 | 부여 조건 |
|---|---|---|
| `university_walk_access` | 캠퍼스 접근성(설명 구성요소) | 점수 ≥ 0.43 AND 최근접 캠퍼스 ≤ 900m |
| `university_life_mix` | 학생생활형 상권 구성(파생 구성요소) | 카페·외식·편의점·세탁·문화 가중평균 |
| `university_commercial_area` | 대학가 생활권(설명 전용 파생) | 최근접 ≤ 900m AND walk ≥ 0.43 AND life_mix ≥ 0.60 AND 결합 ≥ 0.56 |

```text
university_walk_access  = 1 − exp(−Σ 0.5^i/(1+d_i/600) / 0.7)   (R=1,200m)
university_life_mix     = 0.30·카페 + 0.30·외식 + 0.20·편의점 + 0.10·세탁 + 0.10·문화
university_commercial_area = 가중기하평균(walk, life_mix; 0.55, 0.45)
```

대학만 가깝거나 일반 상권만 발달한 지역이 대학상권으로 오분류되지 않도록 **구성요소 하한(0.43·0.60)과 최종 하한(0.56)을 동시에** 둔다.

## 5. 추천모델에서의 역할 — 서비스 적용 상태

- **추천 가중치 0.** `university_commercial_area`는 카페·외식·편의점·세탁·문화 원자점수로 이미 구성되므로, 개인화 추천점수에 독립 가중치로 다시 더하면 같은 상권을 중복 가산한다. 개인화는 기존 **원자 8축**으로 수행하고, 대학가 태그는 **추천 사유·카드 설명**으로만 쓴다.
- **개인화 추천 로직 무변경.** 8축 취향학습 벡터(`PREFERENCE_FEATURES`)와 `preference-features.json`(179 정밀 후보)은 그대로다. 대학 3피처는 8축에 들어가지 않는다.
- **프론트 카드 노출은 별도 과제.** 현재 이 저장소의 프론트는 D 생활환경/결합/대학 태그를 소비하는 경로(`lifestyle-tags` 등)가 없다 — 이 태그들은 `tag/output` 백엔드 산출물이다. `대학가 생활권`을 실제 카드 배지로 띄우려면 프론트 소비 경로를 추가하는 별도 작업이 필요하다.
- UI 문구는 “대학가 생활권 추정 · 최근접 ○○대학교 약 000m(직선거리)”처럼 한계를 밝혀 표시하고, “대학생이 많다”·“도보 10분”으로 단정하지 않는다.
