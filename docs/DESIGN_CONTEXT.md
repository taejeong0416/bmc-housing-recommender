# Design Context — BMC 취향 공공임대주택 추천

## Target audience
- **1차 사용자:** 부산 청년·무주택 세대구성원. 처음 공공임대를 알아보는 20~30대. 청약·자격 용어가 낯설고, "내 취향·예산에 맞는 동네가 어디냐"를 알고 싶다.
- **2차 관객:** 해커톤 심사위원. 첫인상(온보딩)과 지도·추천 화면에서 완성도를 평가한다.

## Use cases
1. 기본조건(지역·예산·주택조건) 입력 → 가상매물 A/B 비교로 생활취향 학습(pairwise) → 취향 진단·직접 보정 온보딩.
2. 지도+목록에서 생활취향 적합도순 추천 탐색, 관심(하트) 담기.
3. 단지 상세(기본·비용·인프라·교통) 확인, 청약센터로 연결.
4. 마이페이지에서 내 자격 요약·관심목록 확인.

## Brand personality / tone
**신뢰형 공공서비스.** 관공서다운 신뢰감 + 요즘 감성. 차갑지 않되(청년 대상) 요란하지 않게(공공기관). teal(#047480) 앵커 — 부산·바다·BMC 연상. 청약/행동은 gold(#f6c026)로 공식적 강조. 본인인증·자격·공고 같은 신뢰 지표를 1급 정보로 취급.

## Voice & microcopy
공공서비스 신뢰 톤 — 확정형·간결·존댓말, 사용자가 다음에 뭘 하는지 한 줄로.
- **구현 상태를 문구로 고백하지 않는다.** "아직 연결 전", "아직 반영되지 않지만", "준비예요/준비 중이라", "데모라서" 같은 내부 미완성 상태를 본문 카피에 노출 금지. 화면에 보이는 입력·데이터·버튼은 실제로 되는 것처럼 확신 있게 쓴다(§죽은 버튼과 한 쌍).
- **신뢰 지표(자격·공고·인증)는 1급 정보, 확정형으로.** "자격 정보는 신청 가능한 공고를 가려내는 데 쓰여요"(O) / "아직 후보 수엔 반영 안 되지만 맞춰드릴 준비예요"(X).
- **진짜 죽은 버튼만** 명시적 '준비 중' 토스트(`soon()` 헬퍼)로 처리 — 보이는 폼·수치엔 disclaimer를 달지 않는다.
- 숫자는 사용자 언어로. 내부 지표 나열("조건 통과 12개 · 데이터 보유 8개")보다 "지금 조건에 맞는 매물 12곳"처럼, 강조는 `tabular-nums`+색으로.

## Design system
- **폰트:** Pretendard(본문·제목 공용). 가격·점수·수치는 `tabular-nums`로 신뢰감. 별도 quirky 폰트 금지(신뢰 저해).
- **색:** teal 계열 스케일 + teal로 미세 틴트한 뉴트럴. gold는 청약/최상위 CTA 전용. 순검정·순백 금지.
- **레이아웃:** 카드 남발 금지, 여백 리듬(빽빽/여유 대비), 좌측 정렬 기본. 적합도·가격은 시각적 강조점.
- **모션:** 페이지 로드/상태 변화 위주, transform·opacity만. bounce·elastic 금지.
- **죽은 버튼:** "되는 것처럼" — 구현 가능한 건 실제 동작, 나머지는 '준비 중' 안내(토스트 등). 시연 중 눌러도 어색하지 않게. 문구 규칙은 §Voice & microcopy.

토큰·컴포넌트·상태의 실행 가능한 규격은 `docs/DESIGN_SYSTEM.md`(테마 하네스)에 있다 — UI를 새로 만들거나 고치기 전 함께 읽는다.

## Scope
실서비스 골격까지: 개발용 상단 전환기가 아닌 실제 사용자용 헤더·네비게이션, 화면 간 자연스러운 흐름, 의미 있는 빈 상태.
