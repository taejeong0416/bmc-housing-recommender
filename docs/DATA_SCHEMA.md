## 3. 표기 규칙·함정 (어댑터가 전부 정규화)

- **인코딩:** 전 파일 **CP949**. `iconv-lite`로 `cp949` 디코딩.
- **천단위 콤마:** 금액뿐 아니라 **세대수·주차대수에도** 콤마(`"1,134"`, `"1,248"`). 숫자 파싱 전 `,` 제거.
- **트레일링 공백:** 매입임대 전용면적 `"42.72 "`처럼 값 끝 공백. 전 필드 `trim()`.
- **zero-pad:** 매입임대 방수 `"02"`. 정수 파싱(`typed-units` 방수는 `"1"`로 non-pad).
- **날짜 포맷 혼재 → ISO(`YYYY-MM-DD`) 통일:**
  - 주택정보 `사용승인일`/`준공일자` = `YYYYMMDD` (`19900725`).
  - 가격 `등록일` = `MM-DD-YYYY HH:mm:ss` (`10-27-2023 13:10:05`).
- **금액 단위 = 원.** `평균표준보증금 4,610,000` = 461만 원. 만원 환산·표시는 프론트 포맷터 담당(원본은 원 그대로 보존).
- **승강기설치구분:** `설치`/`미설치` → boolean.
- **매입임대 `주택명`은 단지명이 아님:** 동(洞) 수준 명칭(`광안동`). 표시명으로 쓰지 말 것. `순위`는 대부분 `NA`.
- **주소 괄호 접미(매입임대 핵심 함정):** `매입임대 주택정보`의 `주소`에는 `(동명[,단지명])` 접미가 붙는다 — `…감포로 13-5(광안동,제이엠하우스)`. 가격 CSV `주소`는 순수 도로명(`…감포로 13-5`). **접미를 떼야 조인·지오코딩이 성립**(제거 전 원본 문자열 교집합 4/36 → 제거 후 정확 매칭). 떼어낸 괄호값은 동명·단지명 소스로 재활용(canonical `dong`, 표시명 보조).

## 4. 조인 키 (가격 → 주택정보 결합)

| 유형 | 결합 규칙 |
|---|---|
| **매입임대** | (정규화 `주소`, `호` ≡ 가격 `호명`). 주택정보 주소의 `(…)` 접미 제거 후 도로명 문자열 일치. |
| **행복·통합·재개발** | 주택정보 `임대주택명` ↔ 가격 `사업지구` 문자열 매칭. |

- **명칭 불일치 대비:** 유형단지는 `임대주택명`(사업주체·지구명이 덧붙는 형태)과 가격 `사업지구`가 흔들릴 수 있어 별칭 매핑 파일 `scripts/ingest/complex-aliases.json` 운영(`{ 사업지구별칭: 임대주택명 }`).
- **주택형 prefix 매칭:** 행복주택 가격의 `주택형`은 `19`처럼 주택정보 `주택형`(`19A`, `29A`, `59`…)의 **prefix**일 수 있다. 정확 일치 → prefix 일치 순으로 fallback.
- **통합공공임대 다축 가격:** 한 (임대주택명, 주택형)에 `소득구간 × 가구인원수` 조합으로 여러 가격 행 존재(`가구인원수 0` = 기준가 포함). canonical `Pricing.qualifier`로 흡수.

canonical 스키마(`Complex`/`Unit`/`Pricing`)와 매핑 규칙은 [`PRODUCTION_PLAN.md`](./PRODUCTION_PLAN.md) P0-A-2 참조. 어댑터 계약: `(rows) => { complexes?, units?, pricing?, skipped: {row, reason}[] }`.

**검증 기준(P0-B 어댑터 테스트):** 입력 행수 = canonical 행수 + 사유 있는 스킵 행수(손실 0).

## 5. 실데이터 수령 체크리스트 (P0-A-3)

샘플로 포맷은 검증됨. 실데이터 도착 시 아래를 확인하고, 포맷이 다르면 **해당 어댑터만 교체**(canonical 이후 단계·앱은 무변경).

- [ ] **컬럼 일치:** §2 컬럼명·순서·유형 분기(`임대주택유형`) 동일 여부. 신규 컬럼 유무.
- [ ] **구(區) 커버리지:** 부산 전 구 포함 여부(샘플 = 수영구·기장군).
- [ ] **인코딩:** CP949 유지 여부(UTF-8 전환 시 디코딩 분기).
- [ ] **표기 함정:** 콤마·트레일링 공백·zero-pad·날짜 포맷·주소 괄호 접미가 샘플과 동일한지.
- [ ] **단지 식별자:** BMC가 안정적 단지 ID를 제공하는지(§4 문자열 조인 의존도를 낮출 최선책).
- [ ] **갱신 주기·전달 방식:** 수동 파일 vs API, 주기. 최종 공공데이터포털 등록 스키마와 정합.

## 6. 선도소프트 상권 GIS (SHP 3종, P3-A-2)

> 상권 추천의 근거 데이터. **부산 전역** 반영. 상가-건물은 `LO`/`LA`(WGS84) 내장이라 지오코딩 불필요, 격자 2종은 `.prj`(EPSG:5186/5179)로 4326 재투영. 업종분류는 **KSIC(한국표준산업분류)** 코드 체계다(수영구 샘플의 옛 상권분류와 다름 — `gis/tags.ts` 매핑 근거). 적재 대상 테이블은 PLAN §P2-B-2(`commerce_pois`·`industry_density`·`commercial_zones`).

### 6.1 파일 구성

| 파일(zip) | 성격 | 지오메트리 | 행수 | 좌표 |
|---|---|---|---|---|
| `buld` (상가-건물) | 점포 단위 | 건물 폴리곤 + 대표점 `LO`/`LA` | 161,449 | `LO`/`LA` WGS84 내장 |
| `pop_store` (밀집도 격자) | 5대 업종-인구 밀집도 | 폴리곤(100m 격자) | 79,935 | `.prj`로 4326 재투영(EPSG:5186/5179) |
| `store_use_area` (용도지역 격자) | 상권·용도지역 | 폴리곤(격자) | 29,441 | `.prj`로 4326 재투영 |

### 6.2 주요 컬럼 (실측)

**① 상가-건물 (`buld`)** — 점포 1건 = 1행. 43개 컬럼 중 핵심:
- **업종 분류 3단계(KSIC 코드):** `CMSC_L_CD`(대분류 10종) → `CMSC_M_CD`(중분류) → `CMSC_S_CD`(소분류). 값이 **KSIC 한국표준산업분류** 체계(예: `I212`=비알코올 음료점, `G20405`=편의점, `R10307`=헬스장). 표준산업분류 `SIC_CD`/`SIC_NM` 병기.
- **좌표:** `LO`/`LA` = **WGS84 십진도 내장**(예: 129.1247, 35.1532) → 점 좌표는 변환 불필요.
- **식별·위치:** `CM_NM`(상호), `SPOT_NM`(지점명), `RDNMADR`(도로명주소), `EMD_CD`(읍면동 코드), `PNU`(필지).
- 대분류 분포(부산 전역): 음식 `I2` 56,173 · 소매 `G2` 40,484 · 수리·개인 `S2` 20,870 · 과학·기술 `M1` 13,252 · 교육 `P1` 7,736 · 예술·스포츠 `R1` 6,160 · 부동산 `L1` 6,046 · 시설관리 `N1` 5,778 · 숙박 `I1` 2,646 · 보건 `Q1` 2,304.

**② 5대 업종-인구 밀집도 격자 (`pop_store`)** — 100m 격자 1칸 = 1행:
- **격자:** `GID`(`마라` 접두 + 좌표 인덱스).
- **인구:** `P_Val`(총) · `P_M`/`P_W`(남/녀) · 연령대별 `P_20_Val`~`P_60_Val`(+`_M`/`_W`).
- **5대 업종 점포 수:** `D_CSV`(편의점) · `D_COFFEE`(커피) · `D_KFOOD`(한식) · `D_PHARM`(약국) · `D_SALON`(미용). "총인구 대비 밀집도"는 `D_*`/`P_Val`로 산출.

**③ 상권·용도지역 격자 (`store_use_area`)** — `pop_store`와 동일한 `GID`·`P_*`·`D_*`에 다음 축 추가:
- **`UCODE`/`UNAME`(용도지역 14종):** 제2종일반주거 7,281 · 자연녹지 6,818 · 일반상업 5,471 · 제3종일반주거 4,720 · 미지정 1,875 · 준공업 1,177 · 준주거 1,085 · 제1종일반주거 236 · 그 외(공업·녹지·상업) 소수. quiet 판정은 라벨의 '주거' 포함 여부(`UCODE`→라벨은 `gis/tags.ts` `ZONE_LABEL`).
- **`BSST_YN`(상권 형성 여부):** Y 5,793 → 추천 서사 "상권 형성된 임대주택"의 직접 근거.

### 6.4 표기 규칙·함정 (어댑터가 처리)

- **좌표계 혼재.** 상가-건물은 `LO`/`LA`(WGS84) 내장이라 점 좌표 변환 불필요, 격자 2종만 `.prj`(EPSG:5186/5179)로 4326 재투영. 부산 bbox(위도 34.8~35.8·경도 128.5~129.5) 가드로 재투영 정상성 검증(격자가 bbox 밖이면 실패 처리).
- **업종 매핑은 코드값 기준.** `CMSC_*_NM`(한글) 일부가 인코딩 깨짐 → 라벨 대신 `CMSC_L/M/S_CD` 코드로 매핑(`gis/tags.ts`). 용도지역도 `UCODE`→`ZONE_LABEL`로 안전 매핑.
- **격자 코드 `GID`** 는 `마라` 접두 + 좌표 인덱스(100m 격자). 두 격자 레이어는 `GID`로 상호 조인 가능.
- **커버리지 게이팅.** density 격자는 부산 전역(355단지 전부 포함), zone 격자는 부분 커버(영도·해운대 일부 미포함, 206). 생활 POI 피처는 전역 POI + density로 355 전부 산출하고(`gisCovered = Boolean(densityGrid)`), zone은 `quiet_residential`의 zone항(가중 0.2)에만 쓴다. 데이터 없는 축은 0이 아니라 `null`(태그가이드 §6.7).

### 6.5 정기 갱신 체크리스트

- [ ] **구(區) 커버리지:** 부산 전 구 포함(현재 15개 구 355단지 반영).
- [ ] **코드 체계:** `CMSC_*_CD` 값이 KSIC 유지 여부 — 옛 상권분류로 회귀하면 `gis/tags.ts` 재매핑 필요.
- [ ] **컬럼 일치:** `CMSC_*`·`D_*`·`BSST_YN`·`UCODE`/`UNAME`·`GID` 동일 여부.
- [ ] **좌표:** 상가 `LO`/`LA` 내장·격자 `.prj` 유지 여부.
