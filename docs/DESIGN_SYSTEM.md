# Design System — Be:live

UI를 새로 만들거나 고치기 전에 읽는다. 목적: 화면마다 즉흥으로 다시 그리지 말고, 여기 정의된 **브랜드·토큰·컴포넌트·상태**에서 조합해 일관된 결과를 낸다. 새 규칙이 필요하면 화면에 임시로 넣지 말고 이 문서와 `components/ui`에 먼저 반영한다.

## 0. 원천 (single source)

- **토큰:** `frontend/src/index.css`의 `@theme` — 색·폰트·그림자·모션. 하드코딩 hex 금지, 토큰 유틸(`text-teal`, `bg-panel`, `border-line`…)만 사용.
- **컴포넌트:** `frontend/src/components/ui/*`. 새 패턴은 화면에서 복제하지 말고 여기로 추출해 재사용.

---

## 1. 사용자와 맥락

**1차 사용자:** 부산 청년·무주택 세대구성원. 처음 공공임대를 알아보는 20~30대. 청약·자격 용어가 낯설고, "내 취향·예산에 맞는 동네가 어디냐"를 알고 싶다.

주요 흐름:

1. 기본조건(지역·예산·주택조건) 입력 → 가상매물 A/B 비교로 생활취향 학습(pairwise) → 취향 진단·직접 보정.
2. 지도+목록에서 생활취향 적합도순 추천 탐색, 관심(하트) 담기.
3. 단지 상세(기본·비용·인프라·교통) 확인, 청약센터로 연결.
4. 내 자격 요약·관심목록 확인.

## 2. 브랜드 톤

**신뢰형 공공서비스.** 관공서다운 신뢰감 + 요즘 감성. 차갑지 않되(청년 대상) 요란하지 않게(공공기관). teal(#047480) 앵커 — 부산·바다·BMC 연상. 청약센터 이동은 gold(#f6c026)로 공식적 강조. 장식보다 글자 크기·굵기와 여백으로 위계를 만든다. 본인인증·자격·공고 같은 신뢰 지표를 1급 정보로 취급한다.

## 3. 카피 규칙

공공서비스 신뢰 톤 — 확정형·간결·존댓말, 사용자가 다음에 뭘 하는지 한 줄로.

- **구현 상태를 문구로 고백하지 않는다.** "아직 연결 전", "아직 반영되지 않지만", "준비 중이라", "데모라서" 같은 내부 상태를 본문 카피에 노출 금지. 화면에 보이는 입력·데이터·버튼은 실제로 되는 것처럼 확신 있게 쓴다.
- **신뢰 지표(자격·공고·인증)는 1급 정보, 확정형으로.** "자격 정보는 신청 가능한 공고를 가려내는 데 쓰여요"(O) / "아직 후보 수엔 반영 안 되지만 맞춰드릴 준비예요"(X).
- **진짜 동작하지 않는 버튼만** 명시적 '준비 중' 토스트(`soon()` 헬퍼)로 처리 — 보이는 폼·수치엔 disclaimer를 달지 않는다.
- 숫자는 사용자 언어로. 내부 지표 나열("조건 통과 12개 · 데이터 보유 8개")보다 "지금 조건에 맞는 매물 12곳"처럼. 강조는 `tabular-nums` + 색으로.

## 4. 토큰 요약 (원천은 index.css)

- **색:** teal(#047480)은 글자색, 진한 면(주 버튼·선택된 칩), 테두리로만 쓴다. 옅게 푼 teal 면은 두지 않는다. teal-dark는 hover/active. **gold**는 청약센터 CTA 전용. heart는 관심. 텍스트 위계 ink→body→sub→faint, 경계 line·line-soft, 표면 paper·panel(중립 회색). **순검정·순백 금지.**
- **타이포:** 제목(h1~h3)과 큰 숫자는 Wanted Sans(`font-display`), 본문은 Pretendard(`font-sans`). 제목 굵기는 bold(700), 800은 브랜드 워드마크에만. 수치·가격·점수는 `tabular-nums`. 위계 예: 화면 제목 24~26px, 섹션 제목 17~18px, 필드 라벨 13px semibold `text-body`, 보조 12.5px `text-sub`.
- **반경:** 컨트롤 9px, 목록 항목 7px, 카드 14~18px.
- **표면:** 카드는 흰 바탕에 얇은 `border-line` 테두리. 그림자는 팝오버·토스트·하단 고정 바(`pop`)에만 쓴다.
- **레이아웃:** 카드 남발 금지, 여백 리듬(빽빽/여유 대비), 좌측 정렬 기본. 적합도·가격이 시각적 강조점.
- **모션:** transform·opacity만, ease-out `cubic-bezier(.22,1,.36,1)`. `rise`·`toast-in`. bounce·elastic 금지. `prefers-reduced-motion` 존중(전역 처리).

## 5. 장식 규칙

- 아이콘은 기능이 있을 때만 쓴다. 아이콘만 있는 버튼(닫기, 확대·축소, 모바일 내비), 상태 표시(체크박스, 펼침 화살표, 장점 체크와 감수할 점 빼기), 관심 하트가 해당한다. 섹션 제목, 페이지 제목, 목록 항목마다 붙이는 장식 아이콘은 두지 않는다.
- 알약 배지와 옅은 색 면을 쓰지 않는다. 유형(행복주택 등)은 단지명 아래 메타 줄에 굵은 글자로, 순위는 단지명 앞 회색 숫자로, 점수는 오른쪽 teal 숫자로 둔다. 사진 위에는 '예시 이미지' 표기만 올린다.
- 버튼 글자 끝에 화살표를 붙이지 않는다. 버튼 이름이 결과를 말한다.
- 회색 부연 설명은 판단에 필요한 정보일 때만 한 줄로 둔다. 제목을 다시 풀어 쓰거나 조작 방법을 설명하는 문장("여러 곳을 고를 수 있어요")은 두지 않는다. 제목이 숫자를 품으면 부제를 따로 두지 않는다("조건에 맞는 추천 10곳").

## 6. 컴포넌트 카탈로그 (`components/ui`)

| 컴포넌트 | 용도 | 상태·변형 |
| --- | --- | --- |
| `Button` | 액션 | primary(teal)/outline/gold(청약)/ghost, hover·active(scale .98)·disabled(line 바탕 + faint 글자) |
| `Chip` | 항목이 적은 다중 선택(방 구조) | active teal 채움 / 미선택 흰 배경 테두리 |
| `Segmented` | 단일 선택 소형(중요도) | 배경 panel, 활성 흰 카드 |
| `Select` | 단일 선택 옵션 목록 | **네이티브 `<select>` 금지**. 트리거+팝오버 리스트박스, `value` 기반 `onChange(value)`, `placeholder`. 선택 항목 teal 굵은 글자+check |
| `MultiSelect` | 항목이 많은 다중 선택(지역) | 트리거에 요약("수영구, 해운대구")과 개수, 펼치면 타일 격자 패널. 타일마다 이름과 개수, 고른 타일은 teal 채움, 개수 0은 비활성. 고른 항목은 트리거 아래 뺄 수 있는 칩 |
| `Toggle`/`MustHaveToggle` | 온·오프(추천 설정, 필수시설) | Toggle은 스위치, MustHaveToggle은 체크박스 행 |
| `Card` | 화면 최상위 컨테이너 | 흰 바탕 + 테두리, 카드 남발 금지 |
| `Toast`(`soon()`) | 준비 중 안내·관심 피드백 | 동작하지 않는 버튼 전용 통로 |
| `States` | 로딩·빈 상태·에러 표준 표시 | 제목 한 줄 + 보조 한 줄, 아이콘 없음 |

**목록을 펼치는 UI(드롭다운·메뉴)는 반드시 `Select`류 테마 팝오버로.** OS 기본 옵션창은 테마가 먹지 않아 일관성이 깨진다. 선택지가 7개를 넘는 다중 선택은 칩으로 펼치지 않고 `MultiSelect`로 접는다.

## 7. 상호작용 상태 (모든 컨트롤 공통)

- **hover:** 테두리를 teal 쪽으로 한 단계(`border-teal/45`), 표면은 `bg-panel`.
- **active(선택됨):** teal 채움, 또는 teal 테두리 + teal 굵은 글자(+check).
- **focus:** 전역 `:focus-visible` teal 링(키보드에만). 개별 override 금지.
- **disabled:** 채도·불투명 낮추고 포인터 차단. **왜 막혔는지는 근처 한 줄로** 사용자 행동 언어로 안내.
- **경고**는 색으로 물들이지 않고 문장과 해결 버튼으로 준다(§8).

## 8. 폼·필수조건 패턴

- 폼은 한 열로 읽히게 둔다. 카드 하나 안에서 섹션을 가는 구분선으로 나누고, 섹션은 제목 + 필드로 통일한다. 필수 섹션은 제목 옆 teal 글자 '필수'로만 구분한다.
- 필드 라벨은 13px semibold `text-body`로 두고, 필수 필드는 라벨 끝에 teal `*`를 붙인다.
- 필수 항목이 비어 있어도 진행 CTA는 누를 수 있게 둔다. 누르면 첫 빈 칸으로 스크롤하고, 빈 칸마다 테두리를 진하게 하고(`Select`의 `invalid`) 칸 아래에 한 줄로 알린다("소득구간을 골라 주세요"). CTA를 `disabled`로 두는 건 사용자가 고칠 수 없는 이유(비교할 매물 부족 등)일 때뿐이고, 그 이유와 해결 버튼을 근처에 둔다.
- 대부분 기본값으로 두는 조건은 '세부 조건'으로 접고, 기본값이 아닌 항목이 있으면 접힌 상태에서도 "N개 적용 중"을 보인다.
- 같은 화면이 온보딩 첫 단계와 재방문 편집을 겸하면, 재방문(비교를 마친 사용자)에서는 단계 표시를 빼고 주 버튼을 편집 결과로 가는 동작("이 조건으로 지도 보기")으로 바꾼다.
- 긴 폼은 맞는 매물 수와 다음 단계 버튼을 늘 보이게 둔다. 데스크톱(lg 이상)은 폼 오른쪽에 고정 요약 패널(매물 수, 고른 조건 요약, 버튼)을, 그보다 좁은 화면은 하단 고정 바를 쓴다.
- 요약·카운트는 **사용자 언어**("조건에 맞는 매물 N곳"), 내부 지표 나열·부연 설명 지양(§3).

## 9. 새 UI 체크리스트

1. 기존 `ui/*`로 되나? 되면 재사용, 안 되면 컴포넌트로 추출.
2. 색·간격·반경·그림자가 전부 토큰인가? 하드코딩 0?
3. hover·active·focus·disabled·invalid 5상태를 정의했나?
4. 카피가 구현 상태를 고백하지 않고 확정형인가?(§3)
5. 장식 아이콘, 알약 배지, 옅은 색 면, 버튼 화살표, 불필요한 회색 부연이 없는가?(§5)
6. 모션은 transform·opacity + reduced-motion?
